# Skill: UI / UX Component Libraries (selection reference)

Load ONLY when choosing or integrating a UI component/styling library for a
project, or when the Founder asks "what should we build the UI with?" — not for
routine component work (the chosen library + `web-design-rules.md` +
`css-architecture.md` cover that). This is the LANDSCAPE and the decision, not a
per-component tutorial. One library is chosen per project and recorded in
`business-context.md` + an ADR; after that, this skill is rarely reloaded.

> Scope split: `web-design-rules.md` = visual design principles (type, color,
> spacing, personality). `css-architecture.md` = how to structure styles (BEM,
> tokens, responsive). `motion-design.md` = animation. THIS file = which
> popular, well-supported library to stand on. No overlap.

Full doctrine, checklists, and failure modes: `ui-libraries-reference.md`.
